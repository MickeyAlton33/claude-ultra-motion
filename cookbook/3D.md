# Ultra 3D cookbook

Worked recipes for the `ultra-3d` plugin. `S=${CLAUDE_SKILL_DIR}/scripts` (inside Claude) — from a shell use the
installed path, e.g. `S=$(ls -d ~/.claude/plugins/cache/claude-ultra-motion/ultra-3d/*/skills/ultra-3d/scripts | tail -1)`.
`PY=~/.ultra-3d/venv/bin/python`. Every recipe starts with `$S/doctor.sh` and `$S/new-3d.sh "<name>" --track <track>`,
and commits after each stage. Credits are Meshy credits; everything else is free.

---

## 1. Product hero render (visual · CAD or supplied model · 0 credits)
*"Studio shots and a turntable of our aluminium speaker."*
1. `new-3d.sh "Speaker hero" --track visual`; drop CAD/GLB into `assets/third-party/` (log in credits.md).
2. Blockout: `render.sh assets/third-party/speaker.glb --quick --preset clay --stills hero --turntable 0` → ⛔ user OKs angle/size.
3. Materials: in Blender MCP (bridge on 9877) assign brushed aluminium (metallic 1, roughness 0.28, anisotropic 0.3)
   and save `src/speaker.blend`; or `--material aluminium` for a single-material look.
4. Review: `render.sh src/speaker.blend --quick --preset dark` → 3d-reviewer with the contact sheet + stills.
5. Final: `render.sh src/speaker.blend --final --preset dark` (4K stills, 180-frame Cycles turntable at 1080p),
   plus `--preset white --transparent --stills hero --turntable 0 --name speaker_cutout` for a web/LCP cutout.
6. Optional HDRI: `curl -A "ultra-3d/1.0" https://api.polyhaven.com/files/studio_small_09` → 2k .hdr into
   `assets/polyhaven/`, pass `--hdri` (CC0, log it).
**Gotcha:** the first Cycles render after a Blender update compiles Metal kernels (~3–4 min, once).

## 2. Web hero GLB for R3F (web · Meshy or supplied · 0–50 credits)
*"A 3D sneaker on my landing page, rotatable."*
1. `new-3d.sh "Sneaker hero" --track web`. Brief: budget tier **hero** (≤150k tris, 2048² textures, ≤4 MB).
2. Model: supplied GLB, or Meshy image route (concept image 4 cr + image-to-3D meshy-7.1 textured 30 cr — approve first).
3. Clean in Blender: apply scale (real size ~0.3 m), origin at sole centre, face +Z in glTF; export GLB (no Draco).
4. `PY mesh_check.py exports/sneaker.glb --track web --budget hero` (expect "not compressed" warning only).
5. `render.sh exports/sneaker.glb --quick --preset white` → reviewer (check texture sharpness, baked lighting).
6. `web_optimize.sh exports/sneaker.glb --budget hero --jsx` → `exports/sneaker.web.glb` + `sneakerModel.tsx`.
7. Hand-off: copy to `public/models/`, use the printed `useGLTF` snippet or the gltfjsx component; poster image =
   `render.sh … --preset white --transparent --stills hero --turntable 0`.
**Gotcha:** `optimize` flattens/joins nodes — pass `--keep-structure` if the site animates named parts.

## 3. AI character → rigged → animated (rigged · Meshy · ≈30–40 credits)
*"A stylised fox mascot that waves on our site."*
1. `new-3d.sh "Fox mascot" --track rigged`. Brief: height (~0.9 m), style refs, clips needed (idle, wave, walk).
2. `meshy_check_balance` → plan table: concept image 4 + image-to-3D **meshy-t2.5** (target_polycount 20k) + meshy-n1
   texture 15 + rig 5 (includes walk & run) + animate wave & idle 6 = **30 credits** → ⛔ approval.
3. Concept image in **A-pose**, arms away from body → user picks → image-to-3D → `render.sh … --quick --preset clay`.
4. `meshy_rig` (humanoid) → `meshy_list_animations` (free) → `meshy_animate` with the chosen action ids.
5. `meshy_download_model` (GLB + FBX) → `PY mesh_check.py fox.glb --track rigged` lists skins/joints/clips.
6. Review: turntable of the rest pose + one still per clip mid-motion (Blender: set frame, render) → reviewer looks
   for candy-wrapper wrists, collapsing shoulders.
7. Web: `web_optimize.sh fox.glb --rigged --budget secondary --jsx` (no flatten/join/simplify on skinned meshes);
   drei `useAnimations(animations, ref)` with the clip names from the check report.

## 4. Functional printed part — parametric (print · build123d · 0 credits)
*"A desk stand for my phone (iPhone 16 Pro, 8.25 mm thick with case 11 mm), 65° viewing angle, cable slot."*
1. `new-3d.sh "Phone stand" --track print` → `src/part.py` template with named dimensions.
2. Write `src/stand.py`: `PHONE_T = 11.0`, `CLEARANCE = 0.4` (loose slide), `ANGLE = 65`, `LIP_H = 12`, `WALL = 3.0`,
   `CABLE_W = 12`, `BASE_D = 90` … sketch the side profile, extrude the width, cut the cable slot, fillet > WALL,
   chamfer 0.4 mm on bed edges. Export STL + 3MF + STEP.
3. `PY mesh_check.py exports/stand.stl --track print --expect 80,90,95` → walls, overhangs, bed contact.
4. `render.sh exports/stand.stl --quick --material pla --color "#2b2b2b"` → reviewer (print-engineer checklist).
5. Orientation: print on its side if the lip is a cantilever (layers along the bend) — rotate in CAD.
6. `slice.sh exports/stand.3mf` (P2S, PLA, textured PEI) → time/grams/cost; strong version:
   `--set wall_loops=4 --set sparse_infill_density=30% --set sparse_infill_pattern=gyroid`.
7. Optional: print a 10-minute coupon of the phone slot first.

## 5. Decorative print from an AI mesh (print · Meshy · ≈40 credits)
*"A 12 cm owl figurine to print in PLA matte."*
1. `new-3d.sh "Owl figurine" --track print`. Brief: 120 mm tall, solid, flat base, no thin parts.
2. Plan: 2 × `meshy_text_to_3d` meshy-7.1 untextured previews = **40 credits** (or 2 × meshy-6-lite = 10) → ⛔ approval.
   Prompt adds "solid, thick features, no thin protrusions, flat oval base".
3. Pick one → `meshy_download_model` (GLB/STL) → `assets/meshy/<task>/`.
4. Repair & size: `PY mesh_fix.py owl.glb -o exports/owl.stl --z-up --fit z=120 --remesh 0.4 --thicken 1.6
   --drop-small 1 --center` (voxel remesh makes it watertight; thicken saves open/thin bits).
5. `PY mesh_check.py exports/owl.stl --track print` — Z must read 120 mm; if walls fail, raise `--thicken` to 2.0.
6. Flat base: if bed contact < 25 mm², cut the bottom flat in Blender (bisect at Z = 2 mm, fill) or `meshy_repair_printability` (10 cr).
7. `render.sh exports/owl.stl --quick --material pla --color "#c9b79c"` → reviewer → `slice.sh exports/owl.stl --process "0.12mm High Quality" --orient`
   (tree supports via `--set enable_support=1 --set support_type=tree(auto)` if overhangs > 2 %).

## 6. Meshy → Blender scene (visual · Meshy + Poly Haven · ≈30–60 credits)
*"A cosy desk scene with a ceramic mug and a plant for a blog header."*
1. `new-3d.sh "Desk scene" --track visual`. Brief: 16:9 header, warm morning light, shallow DOF.
2. Free first: Poly Haven models/textures (`/assets?type=models&categories=furniture`, wood/plaster textures), HDRI
   `brown_photostudio_02` (CC0, log all).
3. Meshy only for what's missing (e.g. a specific mug design: image route 34 cr) → ⛔ approval.
4. Blockout in Blender MCP (bridge on 9877): desk plane, props at real size, camera 50 mm at 25° → ⛔ blockout render checkpoint.
5. Dress: materials, sun through a window (area light + gobo), plant/mug placement; save `src/desk.blend`.
6. Render via `execute_blender_code` with `bpy.ops.render.render(write_still=True)` (not `render_viewport_to_path`,
   which ignores the path) or headless: `Blender -b src/desk.blend -o renders/desk_#### -f 1` → reviewer → 4K final.
7. Optionally hand the stills/turntable to the **ultra-motion** pipeline for a short film.

## Setup on a new machine
```bash
# 1. plugin + Meshy key (Keychain)
claude plugin marketplace add MickeyAlton33/claude-ultra-motion
claude plugin install ultra-3d@claude-ultra-motion
claude plugin configure ultra-3d@claude-ultra-motion          # paste msy_… key yourself
claude plugin marketplace add meshy-dev/meshy-3d-agent        # optional Meshy know-how skills
claude plugin install meshy-3d-generation@meshy-3d-agent
claude plugin install meshy-3d-printing@meshy-3d-agent

# 2. tools (Homebrew — ~1.3 GB)
brew install --cask blender openscad@snapshot
brew install ffmpeg uv node
npm i -g @gltf-transform/cli
uv venv ~/.ultra-3d/venv --python 3.12
VIRTUAL_ENV=~/.ultra-3d/venv uv pip install build123d trimesh manifold3d numpy scipy rtree fast-simplification pillow

# 3. Blender Lab MCP (official, pinned v1.0.3; verify the zip against the tag if you like)
mkdir -p ~/.ultra-3d/downloads/blender-mcp-addon && cd ~/.ultra-3d/downloads/blender-mcp-addon
curl -fLO https://projects.blender.org/lab/blender_mcp/releases/download/v1.0.3/mcp-1.0.3.zip
B=/Applications/Blender.app/Contents/MacOS/Blender
$B -b --command extension install-file -r user_default -e mcp-1.0.3.zip
$B -b --python-expr "import bpy; p=bpy.context.preferences; p.system.use_online_access=True; \
  a=p.addons['bl_ext.user_default.mcp'].preferences; a.port=9877; a.use_autostart=False; bpy.ops.wm.save_userpref()"
git clone --depth 1 --branch v1.0.3 https://projects.blender.org/lab/blender_mcp.git ~/.ultra-3d/blender_mcp
claude mcp add --scope user blender-lab -e BLENDER_PATH=$B -e BLENDER_MCP_PORT=9877 \
  -- uv --directory ~/.ultra-3d/blender_mcp/mcp run blender-mcp

# 4. printer defaults
cat > ~/.ultra-3d/config <<'CFG'
ULTRA3D_PRINTER=P2S
ULTRA3D_NOZZLE=0.4
ULTRA3D_PROCESS="0.20mm Standard"
ULTRA3D_FILAMENT="Bambu PLA Basic"
ULTRA3D_PLATE=textured
ULTRA3D_PROJECTS="$HOME/3d"
CFG

# 5. verify
$(ls -d ~/.claude/plugins/cache/*/ultra-3d/*/skills/ultra-3d/scripts | tail -1)/doctor.sh
```
Port 9877 because the ultra-motion pipeline's `blender` MCP (mcp-for-blender, safe mode) auto-starts on 9876.
Using the Blender Lab bridge: open Blender → Edit › Preferences › Add-ons › MCP → **Start** (stop it when done).
